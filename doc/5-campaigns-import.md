# Доработка: импорт кампаний

Описание основного функционала в 1-description.md.

## 1. Задача

Необходимо реализовать начальный импорт кампаний через API учебного стенда. Он должен выполняться только когда в локальной БД нет ни одной кампании.

В списке кампаний в UI, если этот список пуст, должна быть кнопка "Импортировать из Keitaro".
По нажатии кнопки уходит запрос в наш бэк.

Бэк запрашивает список кампаний запросом GET /campaigns.

Потом для каждой кампании запрашивает её потоки запросом GET /campaigns/<id-кампании>/streams

Как поток редиректа выбираем поток, у которого type="forced", а если такого нет, то с position=1.

Как поток офферов выбираем оставшийся после выбоа потока редиректа.

Условия пригодности кампании:
 - У кампании 2 потока.
 - поток редиректа должен иметь признаки:
```
        "state":"active",
        "schema":"redirect",
        "action_type":"http",
        "action_payload":"<url-редиректа>",
        "collect_clicks":true,
        "filter_or":false,
        "offer_selection":"before_click",
        "offers":[],
        "filters": [
            {
                "name": "country",
                "mode": "accept",
                "payload": ["<код-страны-по-ISO-3166-1-alpha-2>"]
            }
        ]
```
 - поток офферов должен иметь признаки:
```
        "type":"regular",
        "state":"active",
        "schema":"landings",
        "action_type":"http",
        "action_payload":null,
        "collect_clicks":true,
        "filter_or":false,
        "offer_selection":"before_click",
        "filters":[],
```
 - поток офферов должен иметь непустой список офферов с признаком "state":"active".
 
Если хоть одно условие пригодности кампании не выполняется, кампания пропускается.

Если после перебора всех кампаний и проверки их пригодности нет ни одной подходящей, на фронту выдаётся сообщение "Нет подходящих кампаний".

Кампания, удовлетворяющая условиям пригодности, сохраняется в БД, причём в ней записывются id потоков и код страны, извлечённый из фильтра потока редиректа.
Потом для кампании выполняется метод sync_from_training_api из backend/app/services/offers.py для импорта офферов.

Запросы к API учебного стенда, реализованы в backend/app/integrations/training_api.py
Методы, реализующие указанные в этом документе запросы, могли быть удалены из указанного файла коммитом 10098504d4a38ac0a1826f07acb21128e7fa91db. Их надо восстановить.

## 2. План доработки

### 2.1. Восстановить методы интеграции

В `backend/app/integrations/training_api.py` восстановить методы:

- `list_campaigns(offset, limit)` — `GET /campaigns`;
- `get_campaign_streams(campaign_id)` — `GET /campaigns/<id>/streams`.

Сервис должен обрабатывать пагинацию, чтобы перебрать все кампании, а не только
первые 100 записей.

### 2.2. Добавить схемы внешних данных

Создать `backend/app/schemas/campaign_import.py` с Pydantic-схемами ответов API:

- внешняя кампания: `id`, `name`, `alias`, `group_id`, `traffic_source_id`, `domain_id`;
- фильтр потока: `name`, `mode`, `payload`;
- оффер потока: `offer_id`, `share`, `state`, `name`;
- поток: `id`, `campaign_id`, `position`, `type`, `state`, `schema`, `action_type`,
  `action_payload`, `collect_clicks`, `filter_or`, `offer_selection`, `filters`, `offers`.

Обязательные поля должны валидироваться: идентификаторы — положительные, название —
непустым, доля оффера — от 0 до 100. Дополнительные поля ответа API игнорировать.
Поле JSON `schema` хранить в Python-модели под именем, не конфликтующим с методом
Pydantic `BaseModel.schema()`.

### 2.3. Реализовать бизнес-логику импорта

В `backend/app/services/campaigns.py` добавить импорт, который:

- разрешён только при пустой локальной таблице кампаний;
- получает все внешние кампании и их потоки;
- выбирает redirect-поток по `type="forced"`, иначе по `position=1`;
- считает второй поток offer-потоком;
- проверяет все условия пригодности из раздела 1;
- проверяет наличие страны в локальном справочнике;
- сохраняет подходящие кампании с ID потоков и кодом страны;
- запускает `offers.sync_from_training_api` для импорта офферов.

Неподходящие кампании пропускать. При ошибке внешнего API или сохранения не оставлять
частично импортированные локальные данные.

### 2.4. Добавить backend endpoint

Добавить `POST /api/campaigns/import`:

- `409`, если локальные кампании уже существуют;
- успешный ответ с `imported_count` и сообщением `Нет подходящих кампаний`, если
  подходящих кампаний не найдено;
- `502` при ошибке API учебного стенда или синхронизации офферов.

### 2.5. Доработать frontend

В списке кампаний при пустом результате показать кнопку `Импортировать из Keitaro`.
Добавить состояние загрузки, вызов endpoint, обновление списка после импорта и вывод
сообщения `Нет подходящих кампаний`.

### 2.6. Добавить проверки

Покрыть тестами методы API-клиента, успешный импорт, запрет импорта при непустой БД,
выбор потоков, все основные условия пригодности, отсутствие подходящих кампаний,
обработку ошибок и отсутствие частичных данных. После реализации выполнить backend
pytest и frontend build.
