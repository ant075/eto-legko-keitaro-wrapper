# Отмена изменений офферов

При изменении состава офферов изменения сохраняются только в рабочем состоянии нашей БД. В Keitaro они отправляются только после явного нажатия кнопки «Опубликовать офферы потока в Keitaro».

Поэтому для отмены нужно хранить два состояния:

- текущее рабочее состояние офферов;
- состояние последней успешной публикации.

## Снимок последней публикации

Для каждой кампании хранится снимок последнего опубликованного состояния, например в таблице `campaign_offer_publications`.

Снимок содержит:

- `campaign_id`;
- `offer_id`;
- `name`;
- `weight`;
- `is_deleted`;
- `position`;
- дату или номер публикации.

Отдельный снимок предпочтительнее хранения полей `published_*` в основной таблице офферов: рабочее состояние и состояние публикации явно разделены, а восстановление выполняется проще.

Поле `is_new` не требуется. Оффер, присутствующий в рабочем состоянии, но отсутствующий в снимке последней публикации, считается добавленным после публикации.

## Создание кампании

После успешного создания кампании и её потоков:

1. сохранить рабочий список офферов;
2. создать идентичный снимок последней публикации;
3. установить `is_dirty = false`.

## Изменение офферов

Добавление, удаление и восстановление офферов изменяют только рабочее состояние в БД:

1. изменить рабочие записи;
2. пересчитать веса;
3. установить `is_dirty = true`;
4. вернуть фронту новое рабочее состояние.

Запросы на изменение потока в Keitaro при этих операциях не выполняются.

## Публикация

При публикации:

1. взять из БД все рабочие офферы с `is_deleted = false`;
2. отправить их одним `PUT` в Keitaro;
3. только после успешного ответа заменить снимок последней публикации рабочим состоянием;
4. установить `is_dirty = false`.

Если запрос в Keitaro завершился ошибкой, рабочее состояние и снимок не менять, а `is_dirty` оставить равным `true`.

## Отмена

При нажатии кнопки «Отмена»:

1. заменить рабочие офферы данными из снимка последней публикации;
2. установить `is_dirty = false`;
3. вернуть восстановленный список фронту.

Запрос в Keitaro не требуется: пока изменения не опубликованы, Keitaro уже содержит состояние из снимка.

## Синхронизация из Keitaro

При запросе офферов потока из Keitaro:

1. получить поток из Keitaro;
2. сформировать рабочий список по правилам синхронизации;
3. сохранить его как текущее состояние;
4. заменить им снимок последней публикации;
5. установить `is_dirty = false`.

## Правило для `is_pinned`

`pin/unpin` — это локальная настройка алгоритма распределения весов. Само по себе это действие:

- не пересчитывает веса;
- не изменяет поток в Keitaro;
- не устанавливает `is_dirty = true`.

Закреплённый оффер влияет на следующий пересчёт весов, который происходит после изменения состава офферов.

На текущем этапе `pin/unpin` сохраняется сразу и не отменяется кнопкой «Отмена». Если после этого изменён состав офферов, отмена возвращает состав и веса к последней публикации, но сохраняет актуальные значения `is_pinned`.

Таким образом, `is_dirty` означает наличие неподтверждённого изменения состава или весов, которое должно быть опубликовано в Keitaro.
